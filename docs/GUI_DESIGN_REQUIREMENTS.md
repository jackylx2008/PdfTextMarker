# GUI 窗口设计要求

本文档规定 Mp3_Processor 桌面 GUI 的窗口结构、交互行为和验收标准，作为后续新增或调整界面时的统一依据。

## 1. 总体设计目标

- 使用单一主窗口承载所有音频处理功能。
- 功能入口、参数配置、运行日志和任务状态必须保持清晰、稳定的纵向层级。
- 各工作流共用日志区和状态栏，不为每个选项卡重复创建。
- 耗时任务必须在后台执行，确保窗口在处理大量文件时仍能响应。
- 路径控件必须支持选择项目目录之外的本地硬盘、移动硬盘和网络挂载目录。

## 2. 固定窗口结构

窗口内容必须严格按照以下顺序从上到下排列：

```text
┌──────────────────────────────────────────────────────────────┐
│ 功能选项卡                                                   │
│ 音频转换 | 元数据更新 | 封面裁剪 | 封面嵌入 | 音频分割 | 配置 │
├──────────────────────────────────────────────────────────────┤
│ 当前选项卡对应的参数设置                                     │
│ 路径、格式、并发数、复选项、预览/执行/取消按钮等              │
├──────────────────────────────────────────────────────────────┤
│ 运行日志与实时输出                                           │
│ 可滚动日志文本、清空日志按钮                                 │
├──────────────────────────────────────────────────────────────┤
│ 状态栏：总体进度、当前状态、运行环境、实际耗时                │
└──────────────────────────────────────────────────────────────┘
```

功能选项卡必须是窗口标题栏下方的第一个主要交互区域。不得在选项卡上方放置业务参数、全局配置表单或运行日志。

## 3. 功能选项卡

- 选项卡栏固定在窗口上方，采用横向排列。
- 至少包含：音频转换、元数据更新、封面裁剪、封面嵌入、音频分割和全局配置。
- 每个选项卡只代表一个独立工作流，不混合无关业务参数。
- 切换选项卡时，只替换参数设置区域；日志内容、任务进度和状态栏必须保留。
- 全局配置应作为独立选项卡存在，不应占用选项卡上方空间。
- 任务运行期间可以查看其他选项卡，但不得重复启动另一个工作流。

## 4. 参数设置区域

- 参数区域紧跟在选项卡栏下方，并位于日志区域上方。
- 页面内容必须与当前选中的功能选项卡一一对应。
- 路径参数使用“文本框 + 浏览按钮”，支持绝对路径和项目外部目录。
- 格式、模式等有限选项优先使用只读下拉框或复选框，避免无效输入。
- 数值参数必须校验类型和范围，并提供明确的中文错误提示。
- 相关参数应按功能分组，对齐标签和输入控件，避免横向拥挤。
- 每个工作流的操作按钮放在参数区域底部，顺序统一为：参数预览、开始执行、取消任务。
- 默认值从配置文件加载；用户在界面中的临时修改只影响当前运行，除非明确提供保存功能。
- 音频转换页应提供输入类型、输出类型、输入目录、输出目录、码率、递归、覆盖、输出验证、最大文件数、递归深度和并发任务数等设置。

## 5. 日志显示区域

- 日志区域固定在参数设置区域下方，不随功能选项卡切换。
- 使用可滚动的多行只读文本框，持续追加运行日志和实时输出。
- 日志至少应区分普通信息、警告、错误和成功消息。
- 推荐使用等宽字体和高对比度配色，便于查看路径、时间和 FFmpeg 输出。
- 提供“清空日志”按钮；清空只影响界面显示，不删除磁盘日志文件。
- 大量日志必须限制界面保留行数，避免长时间任务导致窗口变慢。
- 后台线程不得直接修改日志控件，必须通过线程安全消息队列交由 GUI 主线程更新。

## 6. 底部状态栏

- 状态栏必须位于整个窗口的最下面，并在窗口调整大小时保持可见。
- 状态栏上方显示横向总体进度条。
- 状态文本应显示：就绪、扫描、运行、正在取消、完成、失败或已取消。
- 运行期间应显示当前文件或当前处理对象。
- 完成、失败和取消时应显示真实的 `HH:MM:SS` 任务耗时。
- 可在状态栏右侧显示 FFmpeg 可用状态、Python/Tk 版本等运行环境信息。
- 状态栏高度保持稳定，不应因日志或参数内容增加而被挤出窗口。

## 7. 运行与交互行为

- 同一时间只允许运行一个工作流任务。
- 任务启动后禁用所有“开始执行”按钮和可能改变运行配置的操作。
- 当前任务的“取消任务”按钮应变为可用；取消必须采用安全边界，不强制破坏正在写入的文件。
- 音频并发转换取消后停止提交新文件，等待已经启动的 FFmpeg 任务安全结束。
- 参数校验失败时不得启动后台任务，并应将焦点保留在当前选项卡。
- 任务失败时同时更新日志、状态栏，并使用对话框显示简洁错误摘要。
- 任务完成后恢复所有允许的操作，并保留日志供用户检查。

## 8. 尺寸与跨平台要求

- 参数区和日志区使用可伸缩布局；推荐垂直空间比例约为 3:2。
- 状态栏使用固定内容高度，参数区和日志区承担窗口缩放。
- 设置合理的最小窗口尺寸，避免标签、输入框和操作按钮重叠。
- Windows、macOS 和 Linux 使用相同的信息层级与控件顺序。
- 优先使用 Tkinter/ttk 原生控件和平台字体回退，避免依赖仅在单一操作系统可用的 UI 组件。
- 所有路径通过 `pathlib.Path` 和路径选择器处理，不在界面代码中硬编码盘符或用户目录。

## 9. 验收标准

- 打开窗口后，从上到下能明确看到：功能选项卡、当前参数设置、日志显示、底部状态栏。
- 切换任意功能选项卡时，参数区域正确变化，日志和状态栏不移动、不清空。
- 输入、输出目录可以选择项目外部硬盘位置。
- 启动任务后界面保持响应，日志和总体进度持续更新。
- 任务完成、失败或取消后，状态栏显示正确结果和实际耗时。
- 调整窗口大小后，四个区域的先后顺序保持不变，状态栏始终位于最底部。
